# 2026-04-06 工作日志

## 主题切换 Bug 修复（第三次尝试）

### 问题
主题切换后显示的是上一次选择的主题，而非当前选择的主题。

### 修复内容
1. **修改 switchTheme 方法**：增加 `commitSync` 参数，调用 `commit()` 而非 `apply()` 实现同步写入
2. **修改 showThemeDialog**：使用 `switchTheme(which, true)` 同步保存，然后直接 `recreate()`，不再用 `post()`

### 文件修改
- `MainActivity.java`:
  - `switchTheme(int theme, boolean commitSync)` - 新增同步写入重载
  - `switchTheme(int theme)` - 改为默认异步保存
  - `showThemeDialog()` - 使用同步保存 + 直接 recreate

### 原因分析
之前使用 `apply()` 异步写入，在 `recreate()` 时 SharedPreferences 可能还未写入完成，导致读取到旧值。

## 主题切换不生效修复（第四次尝试）

### 问题原因
1. `switchTheme()` 使用 `apply()` 异步写入 SharedPreferences，Activity 重建时可能未完成
2. `applyThemeNoView()` 从 SharedPreferences 读取时数据可能未写入

### 修复内容
1. `sCurrentTheme` 改为 -1（未初始化）标识
2. `switchTheme()` 立即更新静态变量 sCurrentTheme
3. `switchTheme()` 使用 `commit()` 同步写入 SharedPreferences
4. `applyThemeNoView()` 优先使用静态变量，避免读取失败

### 文件修改
- `MainActivity.java`:
  - `sCurrentTheme` 初始化为 -1
  - `switchTheme()` 更新静态变量 + 使用 commit() 同步写入
  - `applyThemeNoView()` 优先使用静态变量

### 关键修复（第五次尝试）
- **根本原因**：`AppCompatDelegate.setDefaultNightMode()` 不会自动重建 Activity
- **解决方案**：在 `showThemeDialog()` 中选择主题后手动调用 `recreate()`

## 主题切换最终修复（第六次尝试）

### 问题
主题切换完全无效，只是按钮在改变，但界面没有切换到对应主题。

### 根本原因
`MainActivity` 继承的是 `Activity`，而非 `AppCompatActivity`。`AppCompatDelegate.setDefaultNightMode()` 只对 `AppCompatActivity` 及其子类有效。

### 修复内容
1. 将 `MainActivity extends Activity` 改为 `extends AppCompatActivity`
2. 添加 `import androidx.appcompat.app.AppCompatActivity;`
3. 移除 `showThemeDialog()` 中的手动 `recreate()` 调用（AppCompatActivity 会自动重建）

### 文件修改
- `MainActivity.java`:
  - `import android.app.Activity` → `import androidx.appcompat.app.AppCompatActivity`
  - `extends Activity` → `extends AppCompatActivity`
  - 移除主题选择点击事件中的 `recreate()` 调用

### 额外优化
- 浅色模式底部导航栏改为黑色 (#FF000000)，解决虚拟按键看不清的问题
- `values/themes.xml`: `android:navigationBarColor` 改为黑色
