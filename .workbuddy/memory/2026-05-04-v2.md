# 2026-05-05 工作日志

## 修复硬编码绝对路径导致真机 Hook 不生效

### 问题
用户报告真机上 Hook 完全不生效（不管列表空不空，不管怎样改配置），虚拟机正常。
用户怀疑之前把配置文件的硬地址改成了绝对路径导致的问题。

### 根因
`PermissionCache.java` 和 `ContentRulesManager.java` 中使用了硬编码的绝对路径：
- `PermissionCache.java`：`CONFIG_DIR = "/data/data/com.android.clipboardguard/files/"`
- `ContentRulesManager.java`：4 个硬编码路径常量

这些路径是 App 的私有目录，system_server 进程（以 system 用户运行）无法直接访问。
- 虚拟机上 SELinux 较宽松，可能可以访问
- 真机上 SELinux 严格，system_server 无法访问 `/data/data/com.android.clipboardguard/`
- FileObserver 注册在这些路径上也会失败（文件不可访问）

### 修复内容

#### PermissionCache.java
1. 移除 `CONFIG_DIR` 和所有文件名常量
2. 移除所有 FileObserver 相关代码（6 个 FileObserver 实例 + 8 个注册方法）
3. 移除文件修改时间检查逻辑
4. 移除不再使用的 import（FileObserver、File、ExecutorService）
5. 移除 sRefreshExecutor 线程池
6. loadWriteBlockSet/loadReadBlockSet 只保留 ContentProvider 查询
7. refreshWriteBlockSet/refreshReadBlockSet 简化为直接重新加载

#### ContentRulesManager.java
1. 移除 4 个硬编码文件路径常量
2. loadRules/loadReadRules 改为空操作（sLoaded=true），等待广播推送数据
3. 移除所有文件读取逻辑（readFileContent、parseJsonObject 等）
4. 移除 saveRules/getRulesJson 等文件操作方法（App 端已通过 getFilesDir() 直接操作文件）
5. 规则数据完全通过广播更新（updateRulesFromJson/updateReadRulesFromJson）
