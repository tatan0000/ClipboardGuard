## AVD 测试 — sendBroadcastAsUser 权限错误修复（12:15）

**现象**：AVD root 后首次测试，Hook 成功拦截，但广播发送失败：
`Permission Denial: broadcast from android asks to run as user -1 but is calling from uid u0a131; this requires android.permission.INTERACT_ACROSS_USERS_FULL`

**根因**：代码使用了 `UserHandle.ALL`（值=-1），代表跨所有用户广播，需要特殊权限。

**修复**：将 `UserHandle.ALL` 改为 `UserHandle.CURRENT`（当前用户），无需任何额外权限。

**修改文件**：`Hook.java` 第338行附近，`sendBroadcastAsUser` 的第二个参数从 `userHandleAll` 改为 `userHandleCurrent`。

## AVD 测试 — sendBroadcastAsUser 仍失败（14:20）

**现象**：改用 `UserHandle.CURRENT`（值=-2）后，错误变为：
`Permission Denial: broadcast from android asks to run as user -2 but is calling from uid u0a131`

**根因**：`UserHandle.CURRENT` 仍然是跨用户广播（-2 代表任意用户），需要 `INTERACT_ACROSS_USERS_FULL` 权限。

**修复**：使用普通 `sendBroadcast()`，限定 `setPackage(MODULE_PACKAGE)`，同用户内广播无需跨用户权限。

## AVD 测试 — 弹窗成功启动但超时（14:24）

**现象**：广播发送成功，`DialogLaunchReceiver` 也收到了并启动了弹窗，但10秒后超时默认放行。

**根因分析**：
1. Hook 线程（system_server 进程）轮询 `PermissionProvider` 的 `pending` 表
2. `PermissionDialogActivity`（ClipboardGuard App 进程）点击后写入 `pending` 表
3. **问题**：之前用内存 Map 存储 pending 结果 —— 不同进程内存不共享！
4. system_server 进程的 Map 是空的，所以永远轮询不到

**修复**：改用 SQLite 数据库存储 pending 结果，实现真正的跨进程共享。

**同时修复**：弹窗 Activity 的 launchMode 从 `singleTop` 改为 `singleInstance`，确保每次都是新实例。

**修改文件**：
- `PermissionProvider.java`：内存 Map → SQLite 数据库
- `AndroidManifest.xml`：launchMode singleTop → singleInstance

## Chrome弹窗内容和系统重启修复（15:54）

### 问题现象
1. Chrome复制第一次弹窗内容不显示
2. 点允许后马上弹第二个弹窗
3. 点允许就重启

### 根因分析
1. **防抖逻辑bug**：sLastPopupTime.put放在if块外面，导致每次都更新时间，然后继续执行弹窗逻辑
2. **系统重启**：beforeHookedMethod中允许操作后，系统内部回调又触发clip设置，导致IllegalStateException: beginBroadcast() called while already in a broadcast

### 修复
1. 改用afterHookedMethod：让原始setPrimaryClip先执行，然后根据权限决策决定是否用空clip覆盖
2. 修复防抖逻辑：
   - 先更新时间sLastPopupTime
   - 如果在防抖期且有永久权限则正确return
   - 如果没有永久权限需要弹窗但不更新弹窗时间
   - 添加sPendingDialog集合防止重复弹窗

## 修复"点击允许但没有复制"问题（16:33）

### 问题现象
用户点击允许后，剪贴板没有实际写入内容

### 根因分析
- Hook 使用 `XC_MethodReplacement` 完全替换了原始方法
- 允许时返回 `param.getResult()` 只能获取原始方法的返回值
- 但原始方法从未被真正调用，所以剪贴板不会被写入

### 解决方案
1. 在拦截时保存原始方法的引用（保存到 sOriginalMethod Map）
2. 允许时通过反射调用原始方法 `originalMethod.invoke(param.thisObject, param.args)`
3. 这样才能真正执行剪贴板写入操作

### 修改文件
- `Hook.java`:
  - 添加 `sOriginalMethod` Map 保存原始方法
  - 永久允许时调用原始方法
  - 弹窗允许时调用原始方法
- `PermissionProvider.java`: 添加诊断日志
