# 2026-04-03 工作日志

## ClipboardGuard 状态栏 & LSPosed 作用域修复

### 修复记录（19:25）

1. **状态栏与标题栏重叠（各设备高度不同）**
   - 根本原因：之前方案用透明/decor背景或fitsSystemWindows，在不同设备上行为不一致
   - **最终正确方案**：
     - `window.setStatusBarColor(#007AFF)` 直接设为蓝色，与标题栏同色（简单可靠）
     - 标题栏加 `android:id="@+id/toolbar"`
     - `ViewCompat.setOnApplyWindowInsetsListener` 动态获取状态栏高度，`setPadding(left, statusBarHeight, right, bottom)` 给标题栏加 paddingTop
     - 这样标题栏文字永远在状态栏下方，兼容刘海屏/打孔屏/普通屏

2. **LSPosed作用域不推荐系统框架**
   - 原因：AndroidManifest.xml 缺少 `xposedscope` meta-data
   - **修复**：在 application 标签内添加：
     ```xml
     <meta-data android:name="xposedscope" android:value="android" />
     ```
   - 效果：LSPosed 会在模块作用域页面自动推荐并预勾选"系统框架（android）"

## ClipboardGuard Hook 不触发弹窗的根本修复（19:40）

### 问题根因
1. **Hook 目标类错误**：之前 Hook 的是 `android.content.ClipboardManager`（客户端代理），
   该类在 system_server 进程里不会被本地调用（它只是个IPC客户端）。
   正确目标是 `com.android.server.clipboard.ClipboardService`（真正的系统服务端）。

2. **跨进程通信方式错误**：system_server 里注册的 BroadcastReceiver 无法接收来自普通
   App 进程（PermissionDialogActivity）发出的广播。

### 修复方案
- **Hook.java**：改为 Hook `ClipboardService.setPrimaryClip`，兼容 Android 10~14+ 不同参数签名
  - 直接从方法参数 `args[1]`（callingPackage字符串）获取调用方包名，无需 `getPackagesForUid`
  - 使用 `startActivityAsUser(intent, UserHandle.CURRENT)` 启动弹窗（system_server必须用此方式）
- **PermissionResultReceiver.java**：废弃广播方式，改为轮询 ContentProvider（每100ms查一次）
- **PermissionProvider.java**：新增 `/pending/{pkg}` 路径，作为 system_server ↔ App 进程的"结果信箱"
- **PermissionDialogActivity.java**：用户点选后改为调用 `PermissionProvider.writePendingResult()`

## 晚上 20:50 突破（更新版本）

### 关键发现：setPrimaryClip 在父类中！
用 `adb logcat -s ClipboardGuard:* *:S` 拿到完整日志后，问题清晰了：

```
[诊断] ClipboardService 共有 55 个方法
[诊断] setPrimaryClip 重载数量: 0  ← 居然没有！
[Hook无参数失败] com.android.server.clipboard.ClipboardService#setPrimaryClip()#exact
```

**根本原因**：`setPrimaryClip` 方法不在 `ClipboardService` 类中声明，而是在它的**父类**中！

### 新版本（20:51）改进
- 使用 `getMethods()` 获取包括继承的 public 方法
- 检查父类中是否有 `setPrimaryClip`
- 打印方法所属的声明类
